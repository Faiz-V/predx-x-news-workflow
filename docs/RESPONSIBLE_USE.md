# Responsible use

This workflow is designed for transparent, human-reviewed editorial operations.

## Affiliation and account integrity

The account profiles in this repository are current distribution lenses within one controlled PredX editorial system. They are not templates for manufacturing apparently independent users, endorsements, or consensus.

- Public account bios should disclose PredX affiliation clearly.
- Cross-account coordination must not be presented as independent agreement.
- A post should never fabricate personal experience, customer status, ownership, profit, or product endorsement.
- New account identities require fresh public-platform research and an explicit affiliation plan; existing names are not a reusable naming formula.

## Research boundaries

- Inspect only visible public content or an already available signed-in session in read-only mode.
- Do not request, expose, store, or modify credentials, cookies, session storage, or account settings.
- Do not solve CAPTCHAs, rotate proxies, bypass rate limits, or use anti-detection techniques.
- Do not treat search snippets or cached pages as a substitute for a timestamped X demand snapshot.

## Editorial boundaries

- Virality is a selection signal, not verification.
- Preserve source attribution and uncertainty.
- Distinguish allegation, confirmation, proposal, approval, implementation, and enforcement.
- Never invent causes, quotations, metrics, or independent echoes.
- Keep financial advice, guarantees, partisan persuasion, and manipulative engagement bait out of public copy.
- Use `HOLD` instead of filling a quota with weak or stale material.

## Publication boundary

This project does not publish or interact on X. A human editor must verify the final source state, review both language versions, confirm the account and disclosure context, and publish manually through an authorized surface.

## Data handling

The public repository includes synthetic fixtures only. Production run records may contain URLs, visible engagement snapshots, browser-state descriptions, and editorial reasoning; keep them outside public Git history unless they have been deliberately reviewed and redacted.

Never commit `.env` files, browser profiles, cookies, tokens, local dependency bundles, logs, databases, or raw source archives.
